// 00  무슨 문제냐면

지도가 없다. 센서로 보이는 것뿐이다.

안개 낀 벌판을 걷는 사람과 같다. 방향은 알지만 앞은 몇 미터만 보인다. 완벽한 경로를 한 번에 못 짠다.
보이는 데까지 계획해 조금 가고, 새로 보이면 다시 계획하고, 또 조금 간다. 1초에 열 번.
// 01  1단계 — 학교에서 배운 판별식으로 시작

직선이 원을 지나는가? 공통수학2 판별식

# 직선의 식을 원에 대입 -> 이차방정식
D = lin*lin - 4*quad*const
if D <= 0: return False  # 안 지남

# 직선은 무한히 길다. 선분 위일 때만 진짜 충돌
foot = foot_of_perpendicular(center, line)
return is_between(foot, start, end)
한계: 부풀린 원끼리 겹치면 접선이 옆 원을 뚫는다. 1000개 중 19개 실패(전부 겹친 배치), 벽 앞에선 좌우로 57번 진동.
// 02  2단계 — 접점을 노선도로, A*로 최단경로

원 하나씩 말고, 지하철 노선도처럼

충돌 검사를 미리 다 하면 한 번 계획에 2초가 넘었다. 그래서 A*가 그 노선을 실제로 꺼낼 때만 검사했다.
while 열린큐:
    노드 = 큐에서_꺼냄()      # 비용 작은 것부터
    if 부딪힘(노드): continue  # 이때 처음 검사
2,253 ms→24 ms 결과는 소수점까지 동일
한계: 차가 실제로 못 그리는 꺾임이 나오고, 최소 회전 반경과 통로 폭을 동시에 못 다룬다.
// 02-b  가다 만난 작은 교훈 — 후진을 어떻게 막나

금지도, 약한 벌점도 실패했다

탐색이 차의 방향을 몰라 자꾸 뒤로 도는 경로를 골랐다. 세 번 시도.
금지
뒤로 가는 첫 구간을 막음 → 막다른 골목에서 못 빠져나옴
약한 벌점
값 30, 60 → 되돌아가기를 못 막음. 중간값이 제일 나빴다
강한 벌점
값 120 → 둘 다 해결. 되돌아가기 30회 → 0회
제약의 세기는 단조롭지 않다. 완전히 막으면 탈출을 잃고, 약하게 걸면 소용이 없다. 정답은 양 끝 중 하나였다.
// 03  3단계 — 상수로 안 되면, 방법을 바꾼다

차가 실제로 그릴 수 있는 곡선만 잇는다

접선 그래프에선 호가 곧 안전 경계라, 안전 여유와 회전 반경을 분리할 수 없다. 상수를 바꿔 풀 문제가 아니라 표현 방식 자체의 한계였다.
  • 격자로 범위를 줄이되, 칸마다 차의 위치와 방향을 기억
  • 직진·좌우로 조금씩 꺾는 곡선 조각만 이어붙임
  • 차체를 점이 아니라 원 3개로 덮어 충돌 판정
통과 가능한 틈 1.69 m→0.7 m
// 04  실물의 복병 — 시뮬레이터가 안 가르쳐준 것

알고리즘이 아니라 부호와 단위였다

  • 자이로 눈금을 안 맞춰 도는 양이 8배로 찍힘 → 지도가 빙글빙글 돌며 모든 길이 막힘
  • 조향 방향이 반대라 바로잡을수록 나선으로 감겨 들어감
  • 센서 서보 방향이 반대라 지도가 거울처럼 좌우 반전
  • 시뮬레이터 속도를 그대로 써서, 3cm 가고 96cm 갔다고 믿음
  • 자이로 판이 고장 → Arduino가 ω = v·tan(δ) / L 로 대신 계산
시뮬레이터가 "당연히 맞다"고 가정한 것들이 하나씩 깨졌다. 아무리 좋은 알고리즘도 부호 하나 틀리면 차는 엉뚱하게 간다. 기록의 숫자가 원인을 찾아줬다.
